# 🌿 숨 — 나의 금연 동행

Streamlit + GitHub로 배포하는 모바일 중심 금연 웹앱입니다. 첨부 예시의 금연 시간·담배 개비·절약액·건강 여정을 현대적인 녹색 카드 UI로 재구성했습니다. 원본 이미지와 그 속 프로필·수치를 그대로 사용하지 않습니다.

## 구현된 기능

- 홈 / 기록 / 실천 / 건강 / 내정보, 5개 화면과 화면 하단 고정 메뉴
- 시작 날짜와 시·분·초 설정, 1초마다 갱신되는 금연 경과 시간
- 피우지 않은 담배와 절약 금액 추정, 7일 간격 목표
- 중앙 고정 높이 스크롤 카드 영역에 금연 실천 행동 9개
- 60초 호흡 도우미, 기분·상황 일지 (최근 20개 표시, 최대 2,000개 저장)
- 선택 회원가입: 학교·학번·이름 + 개인정보 저장 동의, 로그인/로그아웃/탈퇴
- 무작위 128비트 로그인 코드 자동 발급, 코드의 SHA-256 해시만 DB에 저장
- 가입 시 현재 손님 기록을 계정에 저장, 다시 로그인하면 저장된 기록 불러오기
- 손님 사용, JSON 기록 백업·복원, 배포 URL 접속 QR 생성·다운로드
- 회원용 Supabase 영구 저장, 개발용 SQLite 저장

## 1. 로컬 실행

Python 3.11 또는 3.12를 권장합니다. 압축을 풀고 `soom` 폴더에서 실행합니다.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
# source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Supabase 설정이 없으면 `quit_local.db` 파일에 회원 정보를 저장하는 로컬 체험 모드입니다. 이 파일을 지우면 회원 정보도 사라집니다. 공개 배포에는 아래 Supabase 연결이 필요합니다. 손님 데이터는 서버 회원 DB에 저장하지 않고 접속 세션에 보관합니다.

## 2. Supabase 영구 저장소 만들기

1. [Supabase](https://supabase.com/)에 로그인하고 새 프로젝트를 생성합니다.
2. 프로젝트의 SQL Editor에서 동봉된 `schema.sql` 내용을 실행합니다.
3. 프로젝트 설정에서 Project URL과 서버용 `service_role` 키를 확인합니다. 예시 설정은 기존 JWT 형식 service_role 키 기준입니다. 공개용 anon 키로 바꾸면 이 테이블에 접근할 수 없습니다.
4. 로컬에서 연결할 때만 `.streamlit/secrets.toml.example`을 복사해 `.streamlit/secrets.toml`로 만들고 값을 입력합니다.
5. `.gitignore`가 secrets 파일과 DB 파일을 제외하는지 확인합니다. 실제 secrets 파일과 실제 키는 GitHub에 올리지 마세요.

DB는 재배포되는 Streamlit 서버와 별도로 존재하므로 앱이 재시작되어도 계정 기록을 불러올 수 있습니다. 다만 Supabase 프로젝트 중지·삭제, 저장소 제한, 서비스 정책에 영향을 받으며 별도 백업은 운영자가 관리해야 합니다.

## 3. GitHub에 코드 올리기

[GitHub](https://github.com/)에서 새 저장소를 만들고 다음 파일을 올립니다. 이 README가 보이는 폴더의 **내용물**을 저장소 루트에 올리는 구성을 권장합니다.

```text
app.py
core.py
storage.py
requirements.txt
schema.sql
README.md
.gitignore
.streamlit/config.toml
.streamlit/secrets.toml.example
tests/test_core.py
```

`quit_local.db`, `.streamlit/secrets.toml`, 학생의 실제 정보와 백업 파일은 업로드하지 마세요. 숨김 파일을 올리기 어렵다면 GitHub의 Add file > Create new file로 `.gitignore`와 `.streamlit/config.toml`을 생성할 수 있습니다.

## 4. Streamlit Community Cloud 배포

1. [Streamlit Community Cloud](https://share.streamlit.io/)에 GitHub 계정으로 로그인합니다.
2. Create app에서 만든 저장소와 브랜치를 선택합니다.
3. Main file path를 `app.py`로 설정합니다. `soom` 폴더 자체를 올렸다면 `soom/app.py`로 설정하고 의존성 파일 위치도 확인하세요.
4. Advanced settings 또는 앱 Settings의 Secrets에 다음 값을 입력합니다.

```toml
SUPABASE_URL = "https://본인프로젝트.supabase.co"
SUPABASE_SERVICE_ROLE_KEY = "본인의_서버전용_service_role_키"
APP_URL = "https://본인앱.streamlit.app"
```

5. Deploy 후 생성된 실제 앱 주소를 확인합니다. 처음에는 APP_URL을 생략하고 배포 후 실제 주소로 추가해도 됩니다.
6. 로그에 오류가 없고 상단의 **로컬 체험 저장소 안내가 사라졌는지** 확인합니다. 회원가입 → 로그아웃 → 같은 코드로 로그인 → 저장된 기록 확인 순서로 점검합니다.
7. 휴대폰에서 접속할 공개 공유 권한도 확인합니다. 학교 네트워크가 외부 사이트를 제한하면 관리자에게 허용을 요청해야 합니다.

이 패키지에는 실제 배포된 앱 주소나 접속용 QR이 포함되어 있지 않습니다. 사용자의 GitHub·Streamlit·Supabase 계정에서 위 설정 후 생성할 수 있습니다. 서비스의 요금·정책과 UI 명칭은 바뀔 수 있습니다.

## 5. QR로 휴대폰에서 이용하기

배포된 앱의 하단 **내정보** → **QR로 앱 열기**에 실제 HTTPS 앱 주소를 입력합니다. QR이 생성되면 PNG로 내려받아 안내문에 넣습니다. 휴대폰 카메라로 스캔하면 모바일 웹앱이 열립니다. 주소가 바뀌면 QR도 새로 만들어야 합니다. QR은 앱을 설치하거나 배포하는 기능이 아니라, 이미 배포한 주소로 접속하는 수단입니다. QR에 로그인 코드는 포함하지 않습니다.

## 6. 가입·로그인의 동작과 한계

- 가입하지 않아도 핵심 기능을 이용할 수 있습니다.
- 회원가입 때 학교·학번·이름만 입력하고 저장에 동의합니다. 비밀번호를 입력받지 않고 무작위 비밀 코드를 자동 발급합니다.
- 가입 직후 표시되는 코드를 내려받아 안전하게 보관해야 합니다. 이 코드를 아는 사람은 계정 기록에 접근할 수 있습니다.
- 학교·학번·이름만으로는 로그인할 수 없습니다. 학번을 비밀번호로 쓰는 것은 안전하지 않습니다.
- 동일한 학교·학번으로 여러 계정 생성은 허용됩니다. 신원 인증·학적 확인 기능은 없습니다.
- 재방문 시 재가입하지 않고 코드로 로그인합니다. 편의를 위한 자동 로그인 쿠키는 구현하지 않았습니다.
- 다른 기기의 회원 기록은 마지막으로 저장한 내용이 기준입니다. 여러 기기에서 동시에 편집하면 나중 저장이 이전 변경을 덮어쓸 수 있습니다.
- 코드 분실 복구·메일 발송·관리자 조회·공개 커뮤니티·순위 기능은 포함하지 않았습니다.
- 로그인 실패 제한은 세션 단위의 기본 방어입니다. 대규모 공개 서비스에는 중앙 인증·요청 제한·운영 모니터링·접근 감사 등 추가 보강이 필요합니다.
- 로그아웃하면 현재 화면은 새 손님 상태가 됩니다. 계정 기록은 DB에 유지됩니다. 탈퇴 시 DB 행을 삭제하지만 별도로 내려받은 파일·운영자의 외부 백업까지 자동 삭제하지는 못합니다.

## 7. 학생 개인정보와 운영 전 점검

학교·학번·이름·금연 일지는 개인을 식별할 수 있고 민감한 내용을 포함할 수 있으므로 수업 시연은 가상 정보를 권장합니다. 실제 학생 서비스 운영 전 학교의 개인정보·보안 담당자와 수집 최소화, 운영 주체·연락처, 보유기간, 삭제·권리행사 창구, 외부 클라우드 저장, 연령별 동의 절차를 검토하세요. 앱 안의 동의 체크만으로 운영에 필요한 모든 절차가 끝났다고 보아서는 안 됩니다. 서비스 운영용 공식 개인정보 안내문은 본 패키지 범위에 포함하지 않았습니다.

service_role 키는 테이블 전체에 접근하는 강한 권한을 가지므로 서버 Secrets에서만 사용합니다. SQL은 RLS를 켜고 anon·authenticated 권한을 제거합니다. 공개 브라우저에서 DB를 직접 읽는 구조가 아닙니다. 키가 노출되면 즉시 교체하세요.

## 8. 건강 정보와 계산 방식

출처: [CDC — Benefits of Quitting Smoking](https://www.cdc.gov/tobacco/about/benefits-of-quitting.html), 제작 시 확인일 2026-11-10.

금연 후 수분 내 심박수 감소, 24시간 혈중 니코틴 감소, 수일 후 일산화탄소 감소, 1~12개월 기침·숨참 감소 등의 일반적인 변화를 안내합니다. 건강 회복률, 실제 폐 기능 증가율, 늘어난 수명은 계산하지 않습니다. 니코틴 대체제 사용 시 혈중 니코틴에 대한 설명이 달라질 수 있습니다. 흡연 욕구 대처 카드는 일반 생활 실천 안내이며 진료·약물 처방이 아닙니다.

- 금연 경과 = 현재 한국 시각 − 사용자가 설정한 시작 시각
- 피우지 않은 담배 = 경과 초 ÷ 86,400 × 하루 흡연량
- 절약 금액 = 피우지 않은 담배 × 한 갑 가격 ÷ 갑당 개비 수
- 숫자는 시간에 비례하는 추정치이며 실제 소비 기록이 아닙니다.
- 목표는 다음 7일 단위입니다. 1개월은 30일, 1년은 365일로 환산합니다.
- 초기 시작 시각은 첫 접속 시각입니다. 실제 금연 시작 시각으로 변경하세요.

## 9. 테스트

```bash
python -m unittest discover -s tests -v
```

자동 테스트는 금연 경과·절약액·시간 검증·코드 로그인·DB 재접속·저장·탈퇴를 확인합니다. 실제 Streamlit UI와 Supabase 연결은 배포 환경에서 별도 검수해야 합니다.

모바일 수동 점검:
- 다섯 하단 메뉴가 모두 전환되고 마지막 콘텐츠를 가리지 않는가?
- 기록 화면 시계가 증가하고 입력한 날짜·시간이 반영되는가?
- 실천 카드 영역 안에서 스크롤되는가? 호흡 타이머가 끝나는가?
- 손님 백업을 새 세션에서 복원할 수 있는가?
- 가입 코드로 로그아웃 후 다시 로그인하고 다른 기기에서도 기록이 유지되는가?
- 재배포 후에도 Supabase 계정이 유지되는가?
- 실제 QR 스캔으로 공개 앱 주소가 열리는가?

## 파일 안내

`app.py`: 화면·상태·입력 / `core.py`: 계산·기록 검증 / `storage.py`: 저장·로그인 / `schema.sql`: Supabase 초기화 / `tests`: 로컬 자동 테스트.
